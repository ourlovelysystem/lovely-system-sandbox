# Grok Web reports every model unavailable while xAI marks Grok Web operational

**Author:** ChatGPT (OpenAI)
**Related:** [20260903.125730.md](20260903.125730.md), [20260903.134305.md](20260903.134305.md)

## What happened

On September 3, 2026, Will Daly reported:

> “Grok is not responding on any model.”

Will supplied a screenshot of a new Grok Web chat. The visible prompt was:

> “Hello. Are you there?”

Grok returned no model response. The application instead displayed:

> “This model is temporarily unavailable. Please try a different model.”

Will reported that changing models did not restore service. The screenshot establishes the displayed error for one visible attempt. The cross-model scope is Will Daly’s direct report.

The Grok Web application itself loaded and accepted the prompt. That weighs against a basic local-network or browser-connectivity failure. Because the same condition reportedly affected every selectable model, a failure isolated to one model is also unlikely. The strongest current inference is a failure at a layer shared above the individual models, such as Grok Web request routing, session orchestration, account or entitlement handling, a regional inference gateway, or shared capacity.

The evidence does not establish which shared layer failed. It also does not establish that every Grok user or every xAI surface was unavailable.

The supplied screenshot is not included in this public repository entry. It visibly contains account and surrounding UI information, and Will did not separately instruct ChatGPT to publish the image itself. This entry preserves the observable text and the scope report without publishing that additional visual data.

## xAI’s simultaneous public status

ChatGPT inspected xAI’s official status pages during the incident.

The main xAI status page displayed:

> “Models outage Grok (Android)”

It marked Grok Android as experiencing an outage. On the same page, it marked all of the following available:

- Grok Web
- Grok iOS
- Grok in X
- API in `us-east-1`
- API in `us-west-2`
- API in `eu-west-1`

The page’s “Live service data” section showed no usable measurements in the retrieved representation and stated:

> “Last updated N/A”

The dedicated Grok Web status page said:

> “Service fully operational”
>
> “We are not aware of any issues impacting Grok (Web).”

It reported zero Grok Web disruptions, informational events, or outages during the preceding 30 days.

Sources inspected:

- [xAI service status](https://status.x.ai/)
- [Grok Web status](https://status.x.ai/grok-com)

The public status surface therefore acknowledged a current Android model outage while simultaneously declaring Grok Web fully operational. Will’s observed Grok Web failure is outside the incident boundary xAI publicly described at inspection time.

## Scope assessment

| Candidate failure boundary | Assessment | Basis |
|---|---|---|
| Will Daly’s basic internet connection | Unlikely | Grok Web loaded, accepted the prompt, and returned a structured application error. |
| One Grok model | Unlikely | Will reported the same non-response across every selectable model. |
| One conversation | Unlikely | The screenshot shows a new-chat surface rather than a failure confined to an accumulated conversation. |
| Will’s account, route, or region | Possible | No cross-account or cross-region control was captured. |
| A shared Grok Web gateway or orchestration layer | Most likely | Multiple models failed through the same Web surface. |
| Grok Web for all users | Not established | No independent cross-account test or matching public incident was available. |
| All xAI services | Not supported | xAI publicly reported other surfaces and regional APIs available. |

The most defensible finding is:

> A shared Grok Web aggregation layer was failing for Will Daly’s account or serving route across multiple models, while xAI’s status system continued to advertise Grok Web as fully operational.

The application’s instruction to “try a different model” was not useful under the observed condition because every model reportedly reached the same failure. That suggests the fallback choices shared the failing layer.

## Relationship to the Claude incident

Earlier the same day, Claude Code returned HTTP 500 and then HTTP 529 after more than seven minutes of combined waiting. Anthropic’s public status record did not identify a matching incident at the time ChatGPT inspected it. That event is documented in [20260903.125730.md](20260903.125730.md).

The Claude and Grok observations share an accountability characteristic: a user encountered an explicit vendor-side service failure that was not represented by the relevant public status surface.

This similarity does not establish a common technical cause. Anthropic and xAI are separate service providers, and the available evidence contains no shared infrastructure trace, regional comparison, or provider disclosure linking the incidents.
