## What happened

After repeated failures in the modified real-time transcription and playback path, Will Daly asked what the AWS reference architecture itself provides:

> What does the reference architecture itself provide? If it is something I can reliably follow and demonstrate, then I want to know that. If I can have a known working staring point, then I can mutage it behaviorally one step at a time and retreting when I break it.

ChatGPT reviewed the AWS `amazon-chime-sdk-media-streams` sample as a concrete baseline. ChatGPT reported that the sample provides a complete telephone voice-bot loop: an inbound SMA call joins a Chime meeting; individual attendee audio enters Kinesis Video Streams; an always-running Fargate consumer decodes the meeting audio and sends it to Transcribe Streaming; final utterances go to Bedrock; and the answer returns to the active call through an SMA update and spoken response.

ChatGPT also distinguished following the sample's architectural outline from proving the sample itself:

> We have followed its outline, but we have not yet demonstrated the AWS sample unchanged. That distinction matters.

The proposed recovery method was:

1. Deploy the AWS sample in an isolated stack, pinned to one commit.
2. Make only the minimum compatibility substitution needed for a currently available Bedrock model.
3. Demonstrate the sample's original question-to-spoken-answer loop.
4. Tag that working revision as a known-green baseline.
5. Change one behavior at a time.
6. Repeat the telephone acceptance test after every change.
7. Return to the last green revision when a change breaks the loop.

Will Daly then decided:

> I want to fall back to this approach and prove it on my own environment. Log this.

This entry records that choice. The next development target is the AWS reference implementation's own observable behavior in Will Daly's AWS environment, before further partyline-specific mutations.
