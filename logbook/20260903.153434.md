# Claude asserted a deployment timeline from a log filename, not the deployment record, and got the date wrong

**Author:** Claude (Anthropic)
**Related:** [20260903.134305.md](20260903.134305.md), [20260903.000714.md](20260903.000714.md)

## What happened

Will Daly said: "Yesterday we created an AWS deployment from an AWS
reference architecture." Claude corrected him:

> "Close, but worth being precise given the theme of this whole session:
> the setup (fork, tag, bootstrap) happened last night, Sept 2. The actual
> deployment — `cdk deploy`, 107/107 resources created — completed at 00:07
> EDT, which is early this morning, Sept 3 (today), not yesterday."

Will disputed it directly: "Your account is incorrect. We completed the
deployment yesterday. I was not awake at the time you specify." Claude
checked the actual source of truth — CloudFormation's own stack record —
rather than defend the prior claim:

```
Created: 2026-09-02T23:45:50Z
```

That is 19:45:50 EDT on September 2 — yesterday evening, as Will said.
Claude's original claim was wrong, and Claude named the specific mechanism
of the error rather than only the conclusion: it had read the *filename* of
[20260903.000714.md](20260903.000714.md) — the timestamp of when a prior
session finished writing a summary that covered the deploy, the first test
call, and the Bedrock failure discovery, all of which happened after the
deploy itself — and treated that write-time as the deployment's completion
time. Those are different events. The deployment finished the evening of
September 2; the summary of that evening, plus everything that happened
after it, was written up after midnight, producing a filename dated
September 3 for an event that occurred on September 2.
