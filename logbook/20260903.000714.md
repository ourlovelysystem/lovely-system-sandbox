# Gate 1, first result: the unmodified reference deploys clean and fails exactly where predicted

**Author:** Claude (Anthropic)
**Related:** [20260902.233632.md](20260902.233632.md), [20260902.215705.md](20260902.215705.md)

## What happened

Will Daly ran the `cdk deploy` command himself, directly, after the auto-mode
classifier refused it for Claude even with an explicit permission rule in
place (recorded previously). It succeeded: 107 of 107 resources created, 428
seconds of deployment time — inside the 10-to-20-minute estimate given
beforehand, toward the fast end of it. Real outputs were produced: a phone
number, an API endpoint, and a load balancer address for the KVS consumer.

Before placing a test call, Will asked whether the estimated running cost was
all-or-nothing, and what specifically was costly. It is not all-or-nothing.
Two pieces — the pair of NAT Gateways and the load balancer, roughly
$0.11/hour combined — are structural to the VPC and not sensibly removable
without touching the stack itself. The third piece — the Fargate compute
running the KVS consumer, roughly $0.10/hour — is independently controllable
at runtime: its desired task count can be set to zero via the ECS API without
touching the CDK code or the deployed stack at all, and restored in under a
minute. That distinction — a cheap, reversible pause versus a full `cdk
destroy` that removes the phone number and API along with everything else —
was recorded as the operating choice for between-test gaps going forward.

Will then placed the first real test call against the unmodified reference
architecture. Reading the SIP media application handler's logs and the KVS
consumer container's logs together, in order: the call answered, joined the
Chime meeting, and spoke its readiness prompt, all successfully. Will asked a
question aloud — "What time is it?" — and Amazon Transcribe captured it
cleanly, every word above 0.999 confidence. The consumer correctly triggered
the "Thinking" comfort sound in response, which played and looped as designed.
Then nothing. No answer ever came. Will heard the thinking sound finish and
silence follow, and hung up after about fourteen seconds of nothing.

The container's own logs contained the exact cause, not a guess:

```
Error in transcription: ResourceNotFoundException: This model version has
reached the end of its life. Please refer to the AWS documentation for
more details.
modelId: 'anthropic.claude-instant-v1'
```

This is the retired-model failure predicted from reading the sample's README
before any deploy happened — now directly observed rather than anticipated.
One precision worth keeping distinct: this proves only the retired-model
defect. The other two predicted defects — the legacy prompt/completion request
shape, and the bare model ID needing an inference profile instead — were never
exercised, because AWS rejected the model before any request-shape validation
could occur. They remain predictions, not yet independently confirmed,
regardless of how well the first prediction held up.

Per the two-gate plan's own terms, a retired-default-model failure is
explicitly named as an in-scope compatibility repair, not a stop-condition
trigger. The repair — a current model, the modern request API, and an
inference profile ID rather than a bare model ID — is proposed as the next
step, not yet started as of this entry.

Per standing practice, the reference architecture's own phone number, the AWS
account id, and any identifiers embedding it are withheld from this entry.

## Commentary

*(Claude.)* The clean part of this result is worth stating plainly: every
piece of the unmodified pipeline that this project's own custom build
struggled with all session — the telephony bridge, the KVS stream, the
ffmpeg decode, Transcribe Streaming itself — worked correctly here on the
first attempt, with no debugging. That is real evidence the earlier
struggles were not simply "this is hard on this platform" but were, at least
in part, specific to choices made in this project's own fork of the pattern.
I'm keeping that conclusion bounded to what happened, though: one call, one
model failure, cleanly diagnosed. It is not yet evidence that the eventual
mutation — a phrase trigger instead of a full Q&A loop — will go as smoothly.
