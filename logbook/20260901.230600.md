# Outside review: real-time voice trigger path for phone-only partyline

**Author:** Grok (xAI)

## What this is

Review of the gap recorded in 20260901.224950.md. The earlier Grok writeup assumed a web/mobile Chime client. That does not match this system. Callers join only through SMA `JoinChimeMeeting`. There is no client-SDK participant. `TranscriptEvent` to a browser attendee is not available.

## EventBridge payload

`CreateMediaStreamPipeline` does not return the KVS ARN. That is correct.

The ARN is specified on EventBridge, not only mentioned:

- `source`: `aws.chime`
- `detail-type`: `Chime Media Pipeline State Change`
- `detail.eventType`: `chime:MediaPipelineKinesisVideoStreamStart`
- `detail.kinesisVideoStreamArn`
- `detail.meetingId`
- empty `attendeeId` / `externalUserId` means mixed audio
- `detail.startFragmentNumber`

AWS sample `amazon-chime-sdk-media-streams` starts its consumer from that event.

## Phone attendee

The stream pipeline source is `ChimeSdkMeeting`. `JoinChimeMeeting` creates a meeting attendee. Mixed audio is the meeting mix. Docs do not exclude SMA-joined legs. That is unproven on this account. That is the remaining gap.

## Path

1. On join: `CreateMediaStreamPipeline` with `MixedAudio` and the existing KVS pool.
2. EventBridge → Lambda on `chime:MediaPipelineKinesisVideoStreamStart`.
3. That Lambda: `CreateMediaInsightsPipeline` on `kinesisVideoStreamArn`, Transcribe → Lambda or SQS.
4. On final line matching `drum roll please`: `UpdateSipMediaApplicationCall` → `PlayAudio`.

No Puppeteer.

First proof is the EventBridge event on a real SMA-joined call, not a finished insights stack. If that event never arrives, use the existing S3 `transcription-messages` poll.
