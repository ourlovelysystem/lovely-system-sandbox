## What happened

A new Claude Code session opened against the reference architecture repo with
no memory of the prior session. Reorienting from git state and this logbook
surfaced a discrepancy worth naming plainly: the Bedrock compatibility fix
described in the previous entry as verified on a live call — new model,
Messages API request/response shape — existed only as an uncommitted working-tree
diff. It had never been committed. Claude read the diff, confirmed it matched
what the prior entry described, ran `tsc --noEmit` clean, and committed it.

Will Daly then stated that before sleeping, he had instructed Claude to bring
the infrastructure to standby (desired task count zero) to hold down cost, and
that it was confirmed healthy first. That instruction and confirmation are not
recorded in this logbook. Rather than accept the report on faith, Claude
attempted to verify directly and hit expired temporary AWS credentials
(`AWS_CREDENTIAL_EXPIRATION` in the past) sitting in the shell environment,
overriding whatever valid credential source sits underneath. Will independently
reproduced the same failure from his own side. Unsetting
`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN`/
`AWS_CREDENTIAL_EXPIRATION` in the shell revealed a working IAM user
(`arn:aws:iam::867712763388:user/claude`) underneath. Querying ECS directly
confirmed the KVS consumer Fargate service at `desiredCount: 0, runningCount: 0`,
`status: ACTIVE` — the standby report was accurate, now independently confirmed
rather than taken on trust. Restoring it later needs only
`update-service --desired-count 1`, no redeploy.

With the fix committed and independently verified working (per the prior
session's 9/9-question call and full audio reconstruction) plus the
compatibility-commit condition ChatGPT set for `gate1-green`, both conditions
in the recorded Gate 1 plan were already met. Claude pushed `main` to origin
and created the annotated `gate1-green` tag on the fix commit, closing Gate 1
per the plan's own stated terms rather than leaving it implicit.

**Still open, not touched this session:** the cross-project KVS stream
isolation gap recorded previously (unscoped `kinesisvideo:GetMedia` IAM
permission and an unfiltered EventBridge rule letting this stack receive the
other project's media stream) remains unremediated. No IAM or EventBridge
change was made.
